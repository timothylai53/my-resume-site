Please use the following decisions for the three outstanding reporting
behaviors.


1. BLANK PRIOTY

Hide records with blank Prioty from the normal P1/P2/P3/P4 summary by default.

The standard Priority report should display:

P1
P2

Include Blank Priority

control for data-quality/troubleshooting purposes.

including cases such as Low severity and Medium severity where mapped Business
Function is not PT.


2. REMEDIATION PLAN STATUS

Do NOT automatically exclude Closed or Remediated records.

Remediation Status is already an explicit filter for the Remediation Plan
report.

Therefore:

Remediation Status = All
-> include all statuses

If the user selects specific statuses:
-> include only those statuses

Do not introduce an implicit "open items only" business rule.

If a specific default Remediation Status selection is confirmed from the
existing Excel report later, we can configure that default separately.

The aggregation logic itself should remain status-independent.


3. MET OR BREACHED SLA

is a SOURCE field.

Use its existing values for the Remediation Rate report:

Met SLA
Breached SLA
Exception
Open
Overdue

The calculation/business rule that produces Met or Breached SLA is not yet
confirmed.

Keep that derivation as a TODO rather than inventing a formula.


4. DISTINCT COUNT

Keep the existing reporting metric:

Number of Vulnerability
=
DISTINCT COUNT of Unique Reference ID

Every cell, subtotal and Grand Total must independently calculate the distinct
count within its current filters/grouping.

Do not calculate Grand Total by adding visible child cells.


5. CURRENT SYNTHETIC DATA

It is acceptable that the current 1,000-row synthetic dataset has no duplicate
Unique Reference IDs.

Keep the automated duplicate-ID aggregation tests because the reporting engine
must still behave correctly when duplicates exist in future inputs.

Do not alter the current dataset solely to force duplicate IDs into the
reporting summaries.
