3. UNPLANNED REMEDIATION

Use Remediation Planned Date to determine whether a vulnerability has a
remediation plan.

Remediation Planned Date is blank

then classify the remediation plan as:

Unplanned

This is a confirmed rule.


4. PLANNED REMEDIATION HIERARCHY

For records with a valid Remediation Planned Date, the main remediation
planning view should group records by QUARTER first.

The user should then be able to expand a Quarter to see its MONTHS.

Hierarchy:

Quarter
    -> Month

Examples:

2026-Q3
    -> Sep-2026

2026-Q4
    -> Oct-2026
    -> Nov-2026
    -> Dec-2026

2027-Q1
    -> Jan-2027
    -> Feb-2027
    -> Mar-2027

2027-Q2
    -> Apr-2027
    -> May-2027
    -> Jun-2027

Do NOT implement a rule where some future dates automatically display as
months and later dates automatically display as quarters.

Quarter is the parent grouping.

Month is the expandable child grouping.


5. QUARTER DERIVATION

Derive Planned Remediation (Quarter) from Remediation Planned Date.

Standard calendar-quarter grouping:

January-March -> Q1
April-June -> Q2
July-September -> Q3
October-December -> Q4

Display format:

YYYY-Q#

Examples:

15-Sep-2026 -> 2026-Q3
15-Oct-2026 -> 2026-Q4
15-Jan-2027 -> 2027-Q1
15-Apr-2027 -> 2027-Q2


6. MONTH DERIVATION

Derive Planned Remediation (Month) from Remediation Planned Date.

Display format:

MMM-YYYY

Examples:

15-Sep-2026 -> Sep-2026
31-Dec-2026 -> Dec-2026
16-Apr-2027 -> Apr-2027

Keep the underlying value as a real date/date-derived value where appropriate
so chronological sorting is preserved.

Do not sort month names alphabetically.
