=====================================================================
 VM Monthly Report - new Power Query workbook
 BUILD GUIDE (company version)
=====================================================================

FILES (all plain text)
  PQ_Company_M_Code.txt   21 queries, paste one by one
  SaveSnapshot_Script.txt Office Script that saves each month's Medium values
  Snapshots_Headers.txt   one line of headers for the tblSnapshots table
  BUILD_GUIDE.txt         this file

WHAT IS DIFFERENT FROM THE OLD WORKBOOK
  - Only ONE raw ROWG file is read per refresh (the one in the Input folder).
  - Medium history is no longer rebuilt from old raw files. Each month's
    Medium values are saved once into a small table (tblSnapshots).
  - The Medium_History folder, copying and renaming files are no longer needed.
  - Output table names and column names stay the same as the old report
    (tblMediumPT_Automated, "Remediaiton Domain (Latest)", etc.), so the
    Remote Medium Exp PivotTables and KPI formulas can point to them.

MEDIUM RULES USED (same as the old workbook)
  - Status snapshot comes from raw "Remediation Status".
  - Raw filter before matching (Business Function, upper case):
      PT  = PT          (CHECK: confirm in the old qryMediumPT; edit Config if different)
      IVS = IVS, or contains CSR
      AVS = AVS
      CVE = SPM         (baseline "Unique ID (SPM+Hostname)" = raw "Unique Reference ID")
  - Keys: Text.Clean + Trim + Upper on both sides.
  - Same raw ID repeated: first row used (counted in chk_Quality).
  - Planned month: date -> "MMM-yyyy" (en-GB); blank / NA / N/A -> "No Plan Date";
    text that is not a date is kept as it is.
  - Cluster and ICS Reporting Hierarchy - Group/Country come from the baseline table.
  - Planned Within Target (Latest) = planned month >= report month and <= end of report year
    Remediation Plan Expired (Latest) = planned month < report month
    (no status filter in the query; the KPI formulas filter the statuses)

=====================================================================
 PART A - ONE-TIME SETUP
=====================================================================

A1. Keep the old workbook as a backup. Do not change it.

A2. Folders (on the company laptop / OneDrive)
    Create a folder for the new report, with two sub-folders:
      Input     - holds ONLY the current month's raw ROWG file (.xlsx)
      Archive   - raw files of past months (backup only, never read)
    OneDrive: right-click the folder > "Always keep on this device".

A3. Create a new blank workbook and save it in that folder.
    Save often (Ctrl+S), especially before any refresh.

A4. Mapping tables
    Copy the Cluster mapping and the IBS list from the old workbook
    (Paste Special > Values) into a sheet called "Mappings".
    Make each one an Excel table: click inside > Ctrl+T > "My table has headers".
    Table Design > Table Name:
      Cluster mapping -> tblClusterMapping   (headers: ICS Group Country | Cluster)
      IBS list        -> tblIBS              (headers: CIID | ...)
    If your headers are different, keep them and change ClusterCountryColumn,
    ClusterValueColumn or IbsKeyColumn in QUERY 3 Config.

A5. Medium baseline tables
    From the old workbook, copy the four BASELINE tables (the tables the old
    _History queries read, NOT the tblMedium..._Automated outputs).
    Paste Special > Values into four sheets. Ctrl+T on each, then name them:
      tblMediumPT_Base
      tblMediumIVS_Base
      tblMediumAVS_Base
      tblMediumCVE_Base
    Keep all baseline columns, including the old dated columns
    (5 May, 13 May, 31 May, 30 Jun, 31 July).
    Delete these columns if they are present:
      - any dated group from 31 Aug onwards
      - the (Latest) columns and the two planning flag columns
    (The query also drops them automatically, but deleting keeps it clean.)

A6. Snapshots table
    Add a sheet called "Snapshots".
    Select columns A, D and G > Format Cells > Text.
    Open Snapshots_Headers.txt in Notepad, copy the single line, click cell A1, paste.
    The headers spread over A1:I1 (they are separated by tabs).
    Select A1:I2 > Ctrl+T > tick "My table has headers" > OK.
    Table Design > Table Name: tblSnapshots

A7. Queries
    Data > Get Data > From Other Sources > Blank Query.
    Create all 21 queries from PQ_Company_M_Code.txt, in order.
    Rename each query exactly as written (right-click > Rename).
    QUERY 1 pInputFolder: put your real Input folder path.
    QUERY 3 Config: check the PT filter and the other settings.
    If asked about privacy levels: choose Organizational for all sources.
    Errors in src_VMTable, src_MedLongTable, med_ThisMonth, med_Long,
    the four tblMedium..._Automated and chk_Quality are normal at this point.

A8. Close the editor: Home > Close & Load (arrow) > Close & Load To...
    > Only Create Connection > OK.

A9. Put the first raw file in Input (see Part C), then load to worksheets,
    IN THIS ORDER (Data > Queries & Connections > right-click > Load To...
    > Table > New worksheet):
      1. vm_Processed           (wait until it finishes)
      2. med_Long               (wait until it finishes)
      3. tblMediumPT_Automated
      4. tblMediumIVS_Automated
      5. tblMediumAVS_Automated
      6. tblMediumCVE_Automated
      7. chk_Quality

A10. Query properties (right-click > Properties) for EVERY query:
       untick "Enable background refresh"
     For vm_Processed and med_Long ALSO:
       untick "Refresh this connection on Refresh All"
     (Their order matters, so they are refreshed by hand.)

A11. SaveSnapshot script
     Automate > New Script > select all > paste SaveSnapshot_Script.txt
     > rename it SaveSnapshot > Save script.

=====================================================================
 PART B - EVERY MONTH
=====================================================================

  0. Ctrl+S.
  1. Move last month's raw file from Input to Archive.
     Put the new raw ROWG file in Input. Input must hold ONE .xlsx file.
  2. Right-click vm_Processed > Refresh. Wait.
  3. Right-click med_Long > Refresh. Wait.
  4. Data > Refresh All. Wait.
  5. Open chk_Quality and check:
       Files in Input folder = 1
       med_Long is for the same month as vm_Processed = 1
       Duplicate rows in saved Snapshots = 0
       other counts look normal compared with last month
  6. Automate > SaveSnapshot > Run.
  7. Data > Refresh All again (the outputs now show the month as History).
  8. Refresh the PivotTables if they did not refresh, check the report, Ctrl+S.

  Redoing a month: put that month's raw file back in Input and repeat
  steps 2 to 6. SaveSnapshot replaces that month in tblSnapshots.

=====================================================================
 PART C - FIRST TIME: REBUILD HISTORY FROM 31 AUG
=====================================================================

The old workbook rebuilt 31 Aug onwards from the raw files in its
Medium_History folder. Replay those months once, oldest first:

  1. Copy the August raw file (e.g. VM_2026-08) into Input.
     Do Part A9 (first time only), then Part B steps 2 to 6.
  2. Move it to Archive. Put the September raw file in Input. Part B steps 2 to 6.
  3. Same for October (and any later month).

After each month, compare with the old report's columns for that month
(see Part D). After the last month, tblSnapshots holds every month from
31 Aug, and the old Medium_History folder is no longer needed.

=====================================================================
 PART D - CHECK AGAINST THE OLD WORKBOOK (same month, same raw file)
=====================================================================

  vm_Processed vs old qryRawVM output:
    - row count
    - counts of Prioty P1 / P2 / P3 / P4 / blank
    - counts of Cluster values, IBS / Non-IBS, Within SLA? values
    A quick way: a PivotTable on each table with the field in Rows and
    Count of Unique Reference ID in Values.

  tblMedium..._Automated vs old tblMedium..._Automated, for each type:
    - row count (must be equal: every baseline row is kept)
    - counts of values in "Remediation Status (<month>)"
    - counts of values in "Planned Remediation (Month) (<month>)"
      (look for "Sep" vs "Sept" - both workbooks use the same en-GB setting)
    - SUM of Planned Within Target (Latest) and Remediation Plan Expired (Latest)

  Note: with LabelWithYear = true the new month columns are called
  "Remediation Status (31 Aug 2026)"; the old ones were "(31 Aug)".

  Do not replace the old report until every number matches.

=====================================================================
 PART E - PIVOTTABLES AND KPI FORMULAS
=====================================================================

  Summary PivotTables          -> source table: vm_Processed
  Remote Medium Exp PivotTables -> source tables: tblMediumPT_Automated,
                                   tblMediumIVS_Automated, tblMediumAVS_Automated,
                                   tblMediumCVE_Automated
  Rebuild them, or copy the sheets from the old workbook and use
  PivotTable Analyze > Change Data Source for each one.
  Formulas that use the (Latest) columns and the planning flags keep working
  because those column names are unchanged.

=====================================================================
 PART F - IF SOMETHING GOES WRONG
=====================================================================

  "The Input folder must contain exactly one .xlsx file"
      -> leave only one raw file in Input (close it in Excel first; a
         temporary ~$ file is ignored).
  "The raw file is missing these columns"
      -> the raw file layout changed; the message lists the columns.
  Formula.Firewall error
      -> Data > Get Data > Query Options > Current Workbook > Privacy >
         set the sources to Organizational (or ask IT what is allowed).
  med_Long month does not match vm_Processed (chk_Quality)
      -> refresh med_Long, then Refresh All.
  Expression.Error: column not found
      -> a column name in Config or a table name in src_Reference /
         src_MediumBase does not match the workbook. Fix the name there.
  Refresh very slow or Excel "Not Responding"
      -> background refresh is off, so Excel freezes while it works.
         Check Task Manager: if Excel uses CPU, wait. Save before big refreshes.
