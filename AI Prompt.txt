Implement the confirmed vulnerability Priority business logic below.

IMPORTANT:

The existing Excel/template column is named:

Prioty

Keep this spelling where compatibility with the existing workbook requires it.

Internally in the backend/code, a clean variable name such as `priority`
may be used.

Do NOT invent additional priority rules.

==================================================
1. REQUIRED INPUTS
==================================================

Priority calculation depends on:

1. IBS classification
2. Business Function
3. CJ or IF
4. Final Severity Rating

The processing order must be:

Raw Data
    ↓
Derive IBS
    ↓
Map Business Function
    ↓
Check Final Severity Rating eligibility
    ↓
Evaluate CJ or IF + IBS + mapped Business Function
    ↓
Calculate Prioty


==================================================
2. IBS DERIVATION
==================================================

IBS is NOT a raw-data field.

IBS must be derived using:

Raw Data[CIID]

against a separate IBS reference dataset containing:

CIID

Rules:

If Raw Data[CIID] is blank:
    IBS result = blank

If Raw Data[CIID] exists in IBS reference CIID:
    IBS result = "IBS"

If Raw Data[CIID] does NOT exist in IBS reference CIID:
    IBS result = "Non-IBS"

Matching should:
- trim surrounding whitespace;
- use exact CIID matching;
- not guess approximate matches.


==================================================
3. BUSINESS FUNCTION MAPPING
==================================================

Use:

Raw Data[Business Function]

Convert it to one of these standardized categories:

IVS
AVS
CVE
PT

Confirmed mappings:

If Business Function CONTAINS "CSR":
    Mapped Business Function = IVS

If Business Function = AVS:
    Mapped Business Function = AVS

If Business Function = IVS:
    Mapped Business Function = IVS

If Business Function = PT:
    Mapped Business Function = PT

If Business Function = SPM:
    Mapped Business Function = CVE

CSR is a case-insensitive CONTAINS rule.

Examples:

CSR-OSS
ABC-CSR-XYZ
CSR Mobile

all map to:

IVS

For exact mappings AVS, IVS, PT, and SPM:
- trim whitespace;
- compare case-insensitively.

If Business Function cannot be mapped:
    treat it as an unmapped/input-quality issue.

Do not guess a mapped category.


==================================================
4. REQUIRED INPUT CHECK
==================================================

Before calculating Priority, verify that the required inputs are available.

The equivalent Excel logic checked:

IBS
Business Function
CJ or IF
Final Severity Rating

If a required input needed for the calculation is blank or unavailable:

Prioty = blank

Do not assign P1/P2/P3/P4 when the required calculation inputs are missing.


==================================================
5. SEVERITY ELIGIBILITY FILTER
==================================================

Before evaluating the Priority matrix, apply the Final Severity Rating filter.

Calculate Priority for:

CRITICAL

HIGH

MEDIUM only when the Business Function maps to PT.


Therefore:

Critical
    -> eligible for Priority calculation

High
    -> eligible for Priority calculation

Medium + mapped Business Function = PT
    -> eligible for Priority calculation

Medium + mapped Business Function = IVS
    -> Prioty = blank

Medium + mapped Business Function = AVS
    -> Prioty = blank

Medium + mapped Business Function = CVE
    -> Prioty = blank

Low
    -> Prioty = blank

Any other noneligible severity
    -> Prioty = blank


IMPORTANT:

Apply this severity eligibility check BEFORE the Priority matrix.


==================================================
6. PRIORITY MATRIX
==================================================

For records that pass the severity eligibility filter, calculate Priority
using these confirmed rules.

Conceptual matrix:

Condition                    IVS    AVS    CVE    PT

IF-CJ                        P1     P1     P1     P1

IF + IBS                     P1     P1     P1     P1

IF + Non-IBS                 P2     P2     P1     P1

CJ                            P2     P2     P2     P2

Others + IBS                 P2     P2     P2     P2

Others + Non-IBS             P4     P4     P3     P3


==================================================
7. EXACT CONDITION ORDER
==================================================

Evaluate these conditions in this exact top-to-bottom order.

--------------------------------------------------
RULE 1 — IF-CJ
--------------------------------------------------

If:

CJ or IF = "IF-CJ"

Then:

Prioty = P1

This applies regardless of:

IBS / Non-IBS

and regardless of mapped Business Function:

IVS
AVS
CVE
PT

provided the record passed the severity eligibility filter.


--------------------------------------------------
RULE 2 — IF + IBS
--------------------------------------------------

If:

CJ or IF = "IF"

AND

IBS = "IBS"

Then:

Prioty = P1

for all mapped Business Functions:

IVS
AVS
CVE
PT


--------------------------------------------------
RULE 3 — IF + NON-IBS + IVS/AVS
--------------------------------------------------

If:

CJ or IF = "IF"

AND

IBS = "Non-IBS"

AND

Mapped Business Function = IVS OR AVS

Then:

Prioty = P2


Remember:

Business Function containing CSR maps to IVS.

Therefore CSR records follow the IVS Priority rules.


--------------------------------------------------
RULE 4 — IF + NON-IBS + CVE/PT
--------------------------------------------------

If:

CJ or IF = "IF"

AND

IBS = "Non-IBS"

AND

Mapped Business Function = CVE OR PT

Then:

Prioty = P1


Remember:

SPM maps to CVE.

Therefore SPM records follow the CVE Priority rules.


--------------------------------------------------
RULE 5 — CJ
--------------------------------------------------

If:

CJ or IF = "CJ"

Then:

Prioty = P2

This applies to:

IBS
Non-IBS

and all mapped Business Functions:

IVS
AVS
CVE
PT

provided the Severity eligibility condition has already passed.


--------------------------------------------------
RULE 6 — OTHERS + IBS
--------------------------------------------------

If:

CJ or IF = "Others"

AND

IBS = "IBS"

Then:

Prioty = P2

for all mapped Business Functions:

IVS
AVS
CVE
PT


--------------------------------------------------
RULE 7 — OTHERS + NON-IBS + IVS/AVS
--------------------------------------------------

If:

CJ or IF = "Others"

AND

IBS = "Non-IBS"

AND

Mapped Business Function = IVS OR AVS

Then:

Prioty = P4


--------------------------------------------------
RULE 8 — OTHERS + NON-IBS + CVE/PT
--------------------------------------------------

If:

CJ or IF = "Others"

AND

IBS = "Non-IBS"

AND

Mapped Business Function = CVE OR PT

Then:

Prioty = P3


==================================================
8. PRECEDENCE
==================================================

Condition precedence is TOP TO BOTTOM.

Do not reorder the rules.

In particular:

IF-CJ always matches Rule 1 first.

Therefore:

IF-CJ + IBS
    -> P1

IF-CJ + Non-IBS
    -> P1

IF-CJ + IVS
    -> P1

IF-CJ + AVS
    -> P1

IF-CJ + CVE
    -> P1

IF-CJ + PT
    -> P1

provided the Severity eligibility filter passes.


==================================================
9. UNRECOGNIZED INPUT
==================================================

If all required inputs exist and the severity is eligible, but the input
combination cannot be matched to one of the confirmed rules:

Return:

Check Input

or represent the same state through the application's validation/data-quality
mechanism.

Do NOT silently assign a priority.
